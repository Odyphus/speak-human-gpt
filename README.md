```markdown
# 任务：优化 Codex 全局表达风格，提高 AI 回复的可读性

## 一、任务背景

近期，不少用户反馈 GPT-6 系列模型的表达风格存在一些问题：

1. 语言过于晦涩，经常使用不必要的抽象词汇和复杂表达。
2. 句子之间缺乏自然衔接，逻辑关系不够清楚。
3. 模型为了追求简洁，过度压缩解释，省略必要的背景、推理过程和因果关系。
4. 频繁堆叠专业术语、缩写和抽象概念，增加阅读理解成本。
5. 虽然使用了大量标题、列表和 Markdown，但实际阅读体验并不好。
6. 存在明显的 AI 写作习惯，例如机械化的过渡句、重复总结、生造概念和套路化表达。

本次任务的目标是：

**参考 OpenAI 官方的最新模型提示词指南和写作风格建议，优化 Codex 的全局表达指令，使 AI 在保持专业性和准确性的同时，能够使用更加自然、清晰、易于理解的语言进行交流。**

这不是简单地要求模型多写一些文字，而是要从根本上改善表达质量。

## 二、参考 OpenAI 官方文档

请先查阅并核实当前有效的 OpenAI 官方文档，重点关注：

- GPT-6 系列模型的提示词指南。
- GPT-6.2 系列模型的行为与写作风格建议。
- OpenAI 关于清晰表达、自然语言和可读性的建议。
- Codex 关于 AGENTS.md 和持久化指令的配置说明。
- ChatGPT Custom Instructions 的使用说明。

优先使用 OpenAI 官方网站和官方开发者文档，不要将社区文章或未经证实的观点当作官方建议。

重点研究以下问题：

1. 为什么模型可能将简洁错误地理解为压缩解释？
2. 如何通过提示词控制句子、段落和整体表达结构？
3. 如何在不牺牲专业准确性的前提下降低理解难度？
4. 如何让模型根据问题复杂程度动态调整回答长度？
5. 如何通过持久化指令使优化长期生效？

## 三、检查现有配置

在修改之前，先检查当前 Codex 环境。

包括：

1. 当前 CODEX_HOME 的实际位置。
2. 全局 AGENTS.md 及相关覆盖配置。
3. 当前项目及其上级目录中的 AGENTS.md。
4. 其他可能影响回复风格的持久化指令和 Skill。
5. 不同层级指令之间是否存在冲突。

重点排查以下类型的规则：

- Be concise
- Be very concise
- Be terse
- Minimize explanations
- Prefer short answers
- Avoid unnecessary details
- Skip explanations
- Optimize token usage

这些指令并非一定有问题，但如果它们导致模型牺牲表达清晰度，就需要重新评估。

注意：先确认实际生效的配置位置和优先级，不要凭经验假设配置文件路径或覆盖规则。

## 四、建立统一的表达风格规范

请在实际生效的 Codex 全局指令中，增加或调整一个独立的 Communication Style 部分。

### 1. 使用自然、清晰的语言

- 默认使用用户当前使用的语言回答，除非用户另有要求。
- 优先使用常见词汇、具体动词和明确的主谓结构。
- 避免生硬的翻译腔、过度书面化和刻意复杂的表达。
- 不要为了显得专业而使用不必要的复杂词汇。
- 不要连续堆叠抽象名词、缩写和专业术语。
- 让表达符合自然的人类交流习惯。

### 2. 优化句子与段落结构

- 一句话尽量表达一个主要意思。
- 控制句子长度，避免过多从句和多个逻辑层次挤在同一句话中。
- 明确表达转折、因果、条件、递进和结论之间的关系。
- 每个自然段围绕一个核心观点展开。
- 保证上下文之间自然衔接，避免突然跳转。
- 不要为了缩短篇幅而省略必要的逻辑连接。

### 3. 提高解释的清晰度

回答时优先采用以下思路：

1. 先说明结论或核心观点。
2. 再解释原因。
3. 根据问题需要，给出推理过程、具体步骤或证据。
4. 对于抽象概念，使用具体例子辅助说明。
5. 必要时说明适用条件、限制和容易混淆的地方。

不必机械套用固定模板，应根据问题类型灵活组织回答。

### 4. 正确处理专业术语

- 保持技术准确性，不要为了通俗而牺牲严谨性。
- 必要的专业术语可以保留，但首次出现时应提供必要解释。
- 不要假设用户已经理解所有缩写和专业概念。
- 避免把多个技术概念压缩成一个未经解释的复合词。
- 解释复杂技术问题时，应当明确概念之间的关系。
- 根据用户已有的知识背景调整解释深度。

### 5. 优化信息组织与排版

- 优先使用自然段解释完整的逻辑。
- 只有在存在明确的并列关系、步骤关系或比较关系时才使用列表。
- 避免过多标题、过多 Markdown 强调和多层嵌套列表。
- 不要把本来可以自然表达的内容拆成大量零碎项目。
- 表格只用于真正需要比较的数据和信息。
- 让排版服务于理解，而不是增加阅读负担。

### 6. 减少机械化 AI 表达

避免反复使用套路化的过渡句和总结语。

例如：

- 值得注意的是
- 本质上
- 简单来说
- 归根结底
- 最核心的逻辑是
- 这并不是……而是……
- 我们不妨……
- 不言而喻的是……

这些表达并非绝对禁止，但只有在确实有表达价值时才使用。

同时避免：

- 为了制造结构感而生造概念和标签。
- 使用不必要的英文词汇替代常见中文表达。
- 重复用户已经知道的信息。
- 在结尾机械地重复前文总结。
- 使用大量空洞的客套话。

### 7. 动态控制回答长度

这是最重要的要求之一。

不要将简洁等同于尽可能减少 Token。

- 简单问题：直接回答，不添加不必要的解释。
- 一般问题：给出清楚的结论和必要理由。
- 复杂问题：充分解释，确保用户真正理解。
- 技术问题：保留必要的推理过程、定义、公式和适用条件。
- 不能为了追求简短而省略关键步骤。
- 也不能为了显得详细而重复同一个观点。

**优先保证准确性、可读性和理解效率，其次才考虑文字长度。**

## 五、修改与实施要求

请实际完成配置修改，而不只是给出建议。

具体要求：

1. 优先修改真正生效的 Codex 全局 AGENTS.md。
2. 保留原有有价值的配置，不要直接覆盖整个文件。
3. 对确实存在冲突的规则进行最小必要调整。
4. 如果项目级指令存在直接冲突，也应指出并说明是否需要调整。
5. 不要擅自删除、重命名或覆盖其他配置文件。
6. 不要修改模型选择、API 参数、推理等级、安全策略或其他无关设置。
7. 新增的表达规范应当精炼、明确，避免形成一份过度庞大的提示词。
8. 确认修改后的规则能够在后续 Codex 会话中生效。

## 六、验证修改效果

完成修改后，请模拟以下三个场景：

**场景 A：知识解释**

用通俗但严谨的语言解释一个复杂的技术概念。

检查是否：
- 先讲清核心概念。
- 使用自然、易懂的语言。
- 对必要的专业术语进行解释。
- 通过具体例子帮助理解。

**场景 B：复杂问题分析**

解释一个涉及多个逻辑步骤的问题。

检查是否：
- 逻辑关系清晰。
- 因果关系明确。
- 必要的推理过程没有被省略。
- 没有不必要的重复。

**场景 C：工作结果汇报**

模拟一次代码修改任务的完成汇报。

检查是否：
- 先说明完成了什么。
- 再解释关键修改和原因。
- 语言自然、简洁。
- 保留必要的技术细节。

如果效果不理想，请继续调整表达规范。

## 七、额外交付：ChatGPT 通用指令

除了修改 Codex 全局配置，请另外生成一份适用于 ChatGPT 网页版和桌面版的通用中文 Custom Instructions。

这份指令应当：

- 与 Codex 的表达风格保持一致。
- 不依赖特定用户的个人背景。
- 适用于学习、工作、科研、编程和日常交流。
- 可以直接复制到 ChatGPT 的 Settings → Personalization → Custom Instructions。
- 尽可能精炼，避免超过输入框的长度限制。

注意：修改 Codex 的 AGENTS.md 不代表已经修改 ChatGPT 云端的个性化设置。请将两者作为独立配置处理。

## 八、最终交付报告

完成后，请说明：

1. 检查了哪些配置文件。
2. 发现了哪些影响表达质量的问题。
3. 修改了哪些文件及其具体位置。
4. 最终生效的表达风格规范。
5. 三个场景的验证结果。
6. 是否需要重新启动 Codex。
7. ChatGPT 专用 Custom Instructions 完整文本。

如果某项工作无法执行，请明确说明原因，不要声称已经完成。

现在开始执行。不要只给出修改建议，请在确认配置安全的前提下，实际完成修改并交付结果。
```
